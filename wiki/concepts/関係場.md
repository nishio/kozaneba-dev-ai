## 定義

**関係場(relation field)**は、二項リンクやN項関係よりも一段深い、関係表現の中心単位として 2026-05 の GPT 対話([raw/関係UI議論_GPT.md](../../raw/関係UI議論_GPT.md))で提案された概念。[Gendlin](../entities/Gendlin.md) の関係・側面論を背景に持つ。

> 関係は、あらかじめ独立に存在する二つのノードを後から結ぶものではない。むしろ、未分節な状況全体から、ある側面が持ち上げられ、その過程で項も関係も同時に分節される。([raw/関係UI議論_GPT.md](../../raw/関係UI議論_GPT.md))

つまり「リンク」「N項関係」が前提する「項 → 関係」という順序を反転し、**状況全体 → 側面の持ち上げ → 項・役割・関係の同時分節 → 表示への射影** という流れで関係を扱う。

## 三層モデル

```
Situation / Felt complex  (未分節な状況、原文、違和感、仮説の混合体)
   ↓ lifting out
Aspect                    (持ち上げられた切り口: 類似、差異、媒介、反転、まだ語がない…)
   ↓ formulation
Relation Field            (側面をもとに、項・役割・文脈・根拠を持つ構造。N項とは限らない)
   ↓ projection
表示                       (線、カード、表、議論マップ、タイムライン、文章)
```

[raw/関係UI議論_GPT.md](../../raw/関係UI議論_GPT.md) の Round 3 (Gendlin との照合)で提示された。

## 「逆順」の本質

このパイプラインの核心は、**項は状況から後で取り出される** という順序の反転にある。

普通のグラフモデル:

```
1. ノード A を作る
2. ノード B を作る
3. A と B を線で結ぶ
4. 線にラベルをつける(オプション)
```

→ 「項が先にあって、関係は後から結ぶ」順序。Kozaneba の現状の操作はほぼこれ。

ジェンドリン的順序:

```
1. 未分節な状況がある(原文・会話・違和感)
2. そこから何かが持ち上がる(=側面)
3. 側面を言うと、項が「立ち上がる」(まだ独立に存在していなかった)
4. 関係場として形がついてくる
5. それを必要に応じて線/表/カードに射影する
```

この反転があると以下が可能になる:

- 「まだ語がない」が保存できる(項が立ち上がる前の Aspect 層)
- 同じ状況から複数の関係場候補が生まれてもよい(目的依存)
- 「以前は causes と呼んでいたが refined された」を carry forward として保存できる(項の独立性を仮定しないから)

逆に項を先に立てる設計(普通のグラフ UI、[N項関係](N項関係.md) UI)では、「まず A と B を選んでください、その間の関係を…」となり、A と B の存在自体が確定済みになる。これが思考の初期段階([KJ法](KJ法.md) の「[渾沌をして語らしめる](渾沌をして語らしめる.md)」段階)で硬すぎる原因。

## 具体例

### 例1: 哲学書読解([2021-12 の哲学書読解の実験](../themes/哲学書読解の実験.md) に近い形)

```
Situation:  「Gendlin の "thing" の話を読んでいる。Heidegger の
             "Bewandtnis" と何か関係がある気がするけど、まだ言えない。
             KJ法 の "渾沌をして語らしめる" にも似てる気がする」
             ↓
Aspect:     [何かが受動的に語り出してくる感じ]
             [既存の概念で名指せない違和感]
             [3つの伝統の重なり]
             ※まだ Gendlin / Heidegger / 川喜田 は独立したノードではない
             ↓
Relation    formulation: "経験が自分から立ち上がる" という共通の動き
Field:      participants: Gendlin の thing / Heidegger の Bewandtnis / 川喜田の渾沌
            aspects: 受動性 / 既存語の不十分さ / 三つの並列
            modality: 仮説
            tensions: まだ「同じ」とは言いたくない
             ↓
Projection: 
  - グラフ: 3点を並列に並べた hub として描く
  - 表: 3つの並列項を縦に並べ、共通点・差異の列を持つ
  - 文章: 「Gendlin, Heidegger, 川喜田に共通する受動性…」
```

Situation の段階では Gendlin / Heidegger / 川喜田 はまだ「ノード」ではない。「何か共通点がある」という Aspect が持ち上がった結果として、**事後的に**項として分離してくる。

普通の Kozaneba で 3 つのこざねを先に作って線で結ぼうとすると、「3 つを結ぶ線って何?」という問いに答えを先に要求してしまう。

### 例2: Keichobot 的対話の例([なぜ作るのか](../themes/なぜ作るのか.md) の実例)

```
Situation:  「自分は Kozaneba を作り続けているが、なぜか分からない」
             ↓
Aspect:     [作り続ける動機の不明瞭さ]
             [自分用 vs 他人用のブレ]
             [子供のメタファー的な何か]
             ↓
Relation    formulation: "他人に使われることで成長する" という構造
Field:      participants: 自分 / ツール / 他人 / 成長
            aspects: 子供のメタファー / 多様性の必要 / フィードバックの必要
             ↓
Projection: 文章として「なぜ作るのか」のメモ
            (実際 2021-08-08 に書かれたソース)
```

[Keichobot](../entities/Keichobot.md) との対話が **Situation → Aspect の持ち上げ** を担い、「Kozaneba を作るのは他人に使われて成長させるため」というのが **Relation Field の formulation**、それをメモに書いたのが **Projection**。

## Kozaneba の現状との対応

| Kozaneba の現状の操作 | パイプライン上の位置 |
|---|---|
| こざねを書く | Situation(原文)を保持 |
| こざねを近くに置く | Aspect の暗黙的表現(空間配置で「何か似てる」を保持) |
| グループ化 | Aspect の半明示的表現 |
| 線を引く | **いきなり Projection(関係場をスキップ)** |

つまり Kozaneba は **Situation Pad と Projection View の間に Aspect Tray と Relation Field がない** ことが構造的特徴。「線を引く」= 関係場を経由せずに直接射影する、という操作になっていて、関係の意味論が貧しいまま固定化される。

[Clean Relation Elicitation](../themes/Clean_Relation_Elicitation.md) で提案された4パネル UI は、この欠けている中間層を埋める設計。

## 各層の境界は揺れる(行き来する)

このパイプラインは「綺麗に4ステップで進む」ものではなく、4 つの層を行き来する作業空間として機能する:

- Aspect を持ち上げると Situation の見え方が変わる(Gendlin の `carry forward`)
- Relation Field を formulate しようとして「合わない」と分かると、Aspect Tray に新しい側面が増える
- Projection を切り替える(線→表→文章)と、Relation Field の弱点が見えて Aspect 層に戻る

## 通常のグラフモデルとの違い(モデル比較)

通常のモデル:

```
Node A
Node B
Edge R(A, B)
```

関係場モデル:

```
未分節な状況 S
  ↓ ある焦点化
側面 α が持ち上がる
  ↓
A, B, C が項として見えてくる
  ↓
それらの関係 R が言えるようになる
  ↓
R を言ったことで、S の別の側面 β が見えてくる
```

側面は「ノードの属性」ではなく **状況全体から取り出される切り口**。これは [Gendlin の体験過程理論](体験過程.md) と整合する。

## N項関係との違い

[N項関係](N項関係.md) は二項関係よりリッチだが、まだ「項が先にあって、関係がそれらを結ぶ」という形式主義を残している。関係場ではさらに、**項そのものが状況からの分節として後から取り出される** という前提が加わる。

```
N項関係:        R(A, B, C, D)
関係場:         状況 → 側面 α → そこから A, B, C, D が項として現れる → R がまとまる
```

関係場の構造例([raw/関係UI議論_GPT.md](../../raw/関係UI議論_GPT.md) より):

```
関係場:
  source situation: 元の文章・会話・経験
  lifted aspects: 持ち上げられた側面群
  participants: 関与する対象群
  roles: それぞれの役割
  formulations: これまでの言い方
  tensions: まだ言えていない点
  projections: 表示形式
```

## 「分節過程」の保存

ジェンドリン的には、関係は静的な構造ではなく **分節が進行するプロセス**。したがって関係場は単なるデータ構造ではなく、**履歴を含む過程**として保持される。

```
Relational Process P:
  lifted-aspects: ...
  formulations:
    - 「A は B に似ている」
    - 「いや、C を介した対応と言った方がよい」
    - 「むしろ D が問題を開いている」
  effects:
    - この言い方で思考が進んだか
    - どの側面がさらに見えたか
    - どの記述が後で撤回されたか
```

旧来のグラフUIで「`causes` エッジを消して `condition-enables` エッジを張る」とすると思考の連続性が失われる。関係場では **carry forward**(以前の言い方が保存されたまま洗練される)を一級市民にする。

## 「まだ語がない」の保存

関係場の重要な特徴の一つは、**まだ言語化できていない側面を保持できる** こと。

```
まだ言えていないこと:
- 「類似」では軽すぎる
- 「媒介」なのか「レンズ」なのか未確定
- D で反転することが、この関係の本質かもしれない
```

これは [Gendlin](../entities/Gendlin.md) の [フェルトセンス](フェルトセンス.md) の保存と直結する。UI 上は「[近い] [違う] [まだ言えない] [言葉が強すぎる] [保留]」などのフィット確認ボタンで実装される(cf. [Clean Relation Elicitation](../themes/Clean_Relation_Elicitation.md))。

## 毛玉の再定義

[毛玉問題](毛玉問題.md) は関係場の視点で再定義できる:

> 毛玉とは、未分節な状況から持ち上げられた多様な側面・関係過程を、すべて二項リンクとして投影したため、側面の差異、文脈、生成過程、未確定性が失われた状態。

つまり毛玉は視覚問題ではなく **分節過程の消去**([raw/関係UI議論_GPT.md](../../raw/関係UI議論_GPT.md))。

## 既存系譜との接続

関係場は完全に新しい概念ではなく、以下の系譜の上に立つ:

- **Open Hypermedia**: リンクを文書中の埋め込み命令ではなく、IDと属性を持ち外部リンクベースに保存される第一級オブジェクトとして扱う(Round 2)
- **Wikidata の qualifier/reference/rank**: 単純な property-value で表せない文脈化を行う仕組み
- **RDF 1.2 triple term**: トリプルを別のトリプルの object に置ける「文について文を述べる」標準
- **W3C N-ary Relations**: 確信度・参加者・条件など、二項では表せない関係のパターン
- **Unfolding Edges** (UCLAB): エッジ属性を必要時に展開する意味ズーム
- **IBIS / gIBIS**: Issue, Position, Argument という型つき関係を扱う議論支援
- **ハイパーグラフ研究**: N項関係を分解せずに保持する枠組み

ただしどれも「日常的な知的作業 UI としての実装」には至っていない([raw/関係UI議論_GPT.md](../../raw/関係UI議論_GPT.md))。
