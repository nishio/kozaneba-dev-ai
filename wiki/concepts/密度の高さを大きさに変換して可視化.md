## 定義

**密度の高さを大きさに変換して可視化** は、2025-08 の Canvas 版 Kozaneba プロトタイプ([pKozaneba2025-08-26~27](../../raw/scrapbox_kozaneba/2025-08-26__pKozaneba2025-08-26~27.md)、**Kozaneba 本流ではなく [広聴AI](広聴AI.md) 関連のサイド実験**)で nishio が発見・言語化した可視化原則。

**散布図では一点に潰れてしまう密集域を、付箋の面積として面で可視化する**。

## 実装の経緯

このプロトタイプ([Canvas移行の検討](../themes/Canvas移行の検討.md) も参照):

- UMAP で 2D 化した意見テキスト座標を `NOTE_SIZE=120px` 格子へスナップ
- 同一格子点の付箋数をカウント
- 重複は **螺旋状に空き格子を探して分散配置** → 結果として **密集していたところが面積を持つ**

nishio の言:

> 四角い塊になっているところは基本的に座標を維持する散布図では一点に潰れてしまっているデータ。**密度の高さを大きさに変換して可視化できている**。

実装の具体値([`StickyNotesClustersView.tsx:25-83`](../../work/canvas_kozaneba_prototype/src/StickyNotesClustersView.tsx) と [`scripts/precompute_clusters.js:38-83`](../../work/canvas_kozaneba_prototype/scripts/precompute_clusters.js)):

- `NOTE_SIZE = 120`(px)、`POSITION_SCALE = 4000`(default)
- 螺旋探索: `for (let radius = 0; radius < 20 && !found; radius++)` の同心リング、各リングで外枠のみ走査(`Math.abs(dx) !== radius && Math.abs(dy) !== radius` をスキップ)
- 螺旋で見つからなければ衝突を許容(`occupied.add` のみ)

Scrapbox に書かれていた `SCALE=600`/`2000`/`4000` の実験は **最終的に 4000 で固定**。`POSITION_SCALE = 4000` がプロトタイプ deploy 時の default。

## Kernel Density Estimation との対比

[pKozaneba2025-08-26~27](../../raw/scrapbox_kozaneba/2025-08-26__pKozaneba2025-08-26~27.md) で nishio が KDE と比較:

- KDE ヒートマップ(`resolution=800, bandwidth=0.05`、Apple M1 Pro で 45sec)でも同等のクラスタ発見能力はある
- ただし KDE は **「データサイエンティスト向けの抽象度」** で、一般人には散布図よりさらに抽象的になり理解されにくい
- 付箋なら **「1 つ 1 つが意見」が説明なしで伝わる**(付箋ワークショップ経験者が多いから)

つまりこの可視化は **アルゴリズムの新規性ではなく、ユーザ認知のメタファ選択** が本質。詳しくは [認知メタファのデザイン](../themes/認知メタファのデザイン.md)。

## 過去の失敗事例との対比

[pKozaneba2025-08-26~27](../../raw/scrapbox_kozaneba/2025-08-26__pKozaneba2025-08-26~27.md):

> 散布図の点を半透明にすることで密度を可視化するのは以前にやった。「[内部構造がわかりやすい](内部構造がわかりやすい.md)」というのが僕の肌感だったが、見た目がボケボケしてので見栄えが悪いので採用されなかった。

→ 同じ「密度可視化」課題に対し、**半透明 = 内部構造は見えるが見栄えが悪い**、**面積 = 内部構造はやや潰れるが見栄えが良い**、というトレードオフ。後者を選んだ。詳しくは [内部構造がわかりやすい](内部構造がわかりやすい.md)。

## パラメータのトレードオフ

[pKozaneba2025-08-26~27](../../raw/scrapbox_kozaneba/2025-08-26__pKozaneba2025-08-26~27.md):

> 付箋座標を格子点にすることは、float を bin に入れてる。1 つの bin に入る数が大きくなりすぎないようにしたい、スケールが大きすぎないようにしたい。ここにパラメータのトレードオフがある。

- 格子細かすぎ → スケールが過大、ぐりぐり動かなくなる、一点潰れも解消されにくい
- 格子粗すぎ → 1 マスに集中しすぎてオーバーフロー、螺旋探索が遠くまで及び元のクラスタ位置を破壊

実測値の例:`SCALE=600` で 60〜90 件重複、`SCALE=2000` で 26〜50 件、`SCALE=4000` でほぼ点状でも 15〜35 件は重複。
