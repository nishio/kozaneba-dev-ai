## 定義

**こざね**(小札)は、[Kozaneba](../entities/Kozaneba.md) における情報の単位。「情報の書かれた小さい断片」(nishio による Keichobot との対話、[Kozanebaの次の進む方向についてわかると良い](../../raw/scrapbox_kozaneba/2021-09-01__Kozanebaの次の進む方向についてわかると良い.md))。

語源は梅棹忠夫『知的生産の技術』の「こざね」 ([Kozaneba読書の体験談](../../raw/scrapbox_kozaneba/2024-03-01__Kozaneba読書の体験談.md) の引用):

> 何枚かまとまったら、論理的にすじがとおるとおもわれる順序に、その一群の紙きれをならべてみる。そして、その端をかさねて、それをホッチキスでとめる。これで、一つの思想が定着したのである。こうしてできあがった紙きれのつらなりを、わたしは「こざね」とよんでいる。 — 梅棹忠夫

(ただし梅棹のこざねは「複数の断片を綴じたもの」、Kozaneba のこざねは「個々の断片」を指す点で粒度が異なる。)

## 種類(Kozaneba 実装)

- 通常のこざね(テキスト断片)
- **拡大したこざね** = 重要度を表現するために大きくしたもの、「一手間かけたもの」として [Scrapbox](../entities/Scrapbox.md) のブラケティング相当の意味を持つ([KozanebaにScrapbox的な思い出し効果をつける](../../raw/scrapbox_kozaneba/2021-12-11__KozanebaにScrapbox的な思い出し効果をつける.md))
- **Scrapboxこざね** — Scrapbox の URL を貼ると生成される、より詳細な情報へのリンクを保ったこざね
- **Gyazoこざね** — 画像こざね
- **大きな付箋** — ズームアウトしても読める付箋として nishio が使う([pKozaneba2025-08-26~27](../../raw/scrapbox_kozaneba/2025-08-26__pKozaneba2025-08-26~27.md))

## [Scrapbox](../entities/Scrapbox.md) の「行」との対応

[Scrapboxの行とKozanebaのこざねの対応づけ](../../raw/scrapbox_kozaneba/2023-03-31__Scrapboxの行とKozanebaのこざねの対応づけ.md) より:

- Scrapbox の行が近接して置かれている = こざねが近接して置かれている
- Scrapbox の箇条書きの親子 = Kozaneba のグループ化と類似

nishio が Kozaneba を使っているときのこざねの粒度は、Scrapbox の[長すぎるタイトルを分割するページ]と同程度。これは KJ法 のラベルとしては「細かめ」で、講演資料を作るなどの近いゴールを持つ場合のサイズに相当する。これは厳密には [こざね法](こざね法.md) に近い。

## システム上の制約

- 「2000 枚で限界」(Firebase に保存する JSON のサイズ上限が理由)([Scrapboxの行とKozanebaのこざねの対応づけ](../../raw/scrapbox_kozaneba/2023-03-31__Scrapboxの行とKozanebaのこざねの対応づけ.md))
- 紙の KJ法は 300 枚くらいが限界

## Pipeline 上の位置: 梅棹こざね との定義のズレ

[関係場](関係場.md) の Pipeline(Situation → Aspect → Relation Field → Projection)で見ると、梅棹忠夫のオリジナルの「こざね」と Kozaneba のこざねは位置が違う:

```
梅棹こざね:    断片 + 断片 + 断片 → ホッチキスで綴じた1つの「思想の定着」  ≒ Relation Field
Kozaneba こざね: 1つのテキスト断片                                         ≒ Aspect
```

つまり梅棹こざね は **複数の断片を関係づけて束ねたもの**(=今でいう Relation Field の formulation に相当)で、Kozaneba こざね は **個別の断片**(=Aspect に相当)。両者は名前は同じだが Pipeline 上の層が違う。

## 「源の長文(Situation)を持たない」問題(2026-05-16)

nishio の観察:

> Kozaneba のこざねは Scrapbox のページタイトルに相当するもので、現状のこざねは「ページ本文」に相当するものを持っていない。一方で Scrapbox の「タイトル/本文 1:1」もおかしくて、1 つの長文から N 個の短文(=タイトル/こざね)が生えていると思う。

これは「Kozaneba のこざねは Aspect レベルの単位として、**そこから自分が生えてきた源の長文(Situation)** を構造的に持っていない」という指摘。

| Pipeline | Scrapbox | Kozaneba |
|---|---|---|
| Situation | ページ本文(ただし 1:1 で固定) | **欠落** |
| Aspect | ページタイトル | こざね |
| Relation Field | リンクが弱く担う | 欠落 |
| Projection | リンクグラフ | キャンバス配置 |

詳しくは [源の長文](源の長文.md) を参照。設計含意としては、こざねに `source_situation`(源の長文への参照 + anchor)フィールドを追加することで、**1 長文 → N こざね** の関係を保持できる。
