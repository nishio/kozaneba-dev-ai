このページは 2021 年に書かれた Kozaneba 関連の 102 ページ(うち 39 本が「Kozaneba 開発日記」、残りはタイトルに Kozaneba を含まないが本文で言及)を読んで、その年に起きた設計判断・気づき・後悔・繰り返し現れる課題を時系列で整理したものである。実装の細かい変更履歴ではなく、**未来の自分が「なぜそう設計したか」を思い出せること** を目的にする。

## 概観

2021 年は Kozaneba にとって「**前身ツールから引き継ぎ、自分が使う道具として作り直し、対外的に公開し、自分自身で使い込むことで設計の通奏低音を発見した年**」だった。

- **3-7 月: Movidea 期 / 助走**。2013 年の grouping、2018 年の [Regroup](../entities/Regroup.md)、2019 年の Regroup v2 を経て、2021 年に [Movidea](../entities/Movidea.md) としてゼロから作り直しが始まる。Cypress による自動テストと React + immer + ReactN という技術選択が定まる。
- **8 月: Kozaneba への改名と公開**。月初に名前が [Movidea から Kozaneba へ](../../raw/scrapbox_kozaneba/2021-08-02__2021-08-02Movidea_Kozaneba開発日記.md) 切り替わり、Firestore + Firebase Auth で初のクラウド保存・チュートリアル・ユーザテストが動き出す。月の終わりにはユーザ拡張機能、Scrapbox こざね、リードオンリー共有まで揃う。8/8 の Keichobot との対話 [Kozanebaを作ることで何がどうなればいいのか](../../raw/scrapbox_kozaneba/2021-08-08__Kozanebaを作ることで何がどうなればいいのか.md) で、目的が「自分のため」から「**他の人に使われて成長すること**」へと自覚的に移行した。
- **9 月: 矢印 / アノテーションレイヤー / 物理演算**。Scrapbox のリンクをこざねとして取り込んで整理することで「**近接だけでは関係を表現しきれない**」と気づき、SVG レイヤー上の矢印機能が実装された。ソースコードの依存関係をこざねで可視化する負荷テストも行われ、物理演算の自動配置も試作された。
- **10-11 月: 自分で使い込むフェーズ**。開発日記は減り、その代わりにトートバッグの図案を Kozaneba で並べる、ツェッテルカステン関連の Twitter スレッドを整理するなど、応用が広がる。Runtypes による実行時型チェックも整備された。
- **12 月: 哲学書の読解への応用と Kozaneba 修行**。「[体験過程と意味の創造](../../raw/scrapbox_kozaneba/2021-12-08__Kozaneba_体験過程と意味の創造.md)」の勉強会発表をきっかけに、ハイデッガー「建てること、住むこと、考えること」、メルロポンティ「言語の現象学について」、華厳哲学などの難解図書を Kozaneba で読解する実験が連続する。この過程で「**線がなければ既存の構造を持つ書籍を読むのに不利**」「**Keichobot は言語化し Kozaneba は一次元化する**」という二大テーゼが言語化される。

設計の中で繰り返し見えてくる主題は、(1) **自分のため vs 多くの人のため**、(2) **言語化 (Keichobot) と一次元化 (Kozaneba) の分業**、(3) **近接 vs 線 — 既存の構造を保ったまま新しい構造を入れる方法**、(4) **不確実性削減ムーブ vs 楽さドリブン vs 面白さドリブン**、(5) **デジタル文房具は「子供」のように手元から旅立たせる** — の五つに集約できる。以下、月別に具体を追う。

## 月別タイムライン

### 2021-06 〜 2021-07: 前史と Movidea ゼロから書き直し

- 6/9: [History](../../raw/scrapbox_kozaneba/2021-06-09__History.md) — 2013 年の grouping、2018-19 年の Regroup と Regroup v2、2021 年に Movidea / Kozaneba がある、という系譜が初めて 1 ページにまとまる。
- 7/15: [Movidea 開発日記](../../raw/scrapbox_kozaneba/2021-07-15__2021-07-15Movidea開発日記.md) で **アプリ名が Kozaneba に決まる瞬間**。「Fusen / Postit / Sticky / Sticker」では英語圏のしっくりこなさが残り、いっそ「こざね」と「場」の合成にしようと決断。「白い背景を Ba と呼ぶ」「Kozane + Ba = Kozaneba」。同じ日に「自分の作ってるものは KJ 法よりはこざね法寄り」とも自覚。
  > 単数個人用の、いわば密室むき知的生産技術 — 梅棹忠夫「こざね法」
- 7/16: [Cypress 勉強会](../../raw/scrapbox_kozaneba/2021-07-16__Cypress勉強会.md) — Cypress 採用の理由が後で参照できる形にまとまる。**jsdom では「ちょっと凝ったこと」をするとすぐぶつかる、だから実ブラウザでテストする**。「テストピラミッドの逆」(UI テストを主力にする) を意識的に選択している。後の Kozaneba 開発はこのテスト思想の上に乗っかる。
- 7/29: [Movidea 開発日記](../../raw/scrapbox_kozaneba/2021-07-29__2021-07-29Movidea開発日記.md) — Regroup 時代の「サーバに接続する」というメタファーが不適切だったと振り返り、「ローカルに置く / クラウドに置く」モデルへの移行を決定。HandOff (URL で渡して共同編集) を重視してログインなしを選んだ初期方針も明文化される。

### 2021-08-02〜10: Kozaneba への改名、初リリース、目的の再定義

- 8/2: [Movidea/Kozaneba 開発日記](../../raw/scrapbox_kozaneba/2021-08-02__2021-08-02Movidea_Kozaneba開発日記.md) — 「**不確実なものほど素早く検証するべき**」を理由に、認証より先にデプロイして「操作できるか」を Windows で確認。タイミング的に Movidea → Kozaneba のリネームも今やる。Firebase 匿名認証 + Google OAuth を採用。
- 8/3-5: [開発日記 08-03](../../raw/scrapbox_kozaneba/2021-08-03__Kozaneba開発日記2021-08-03.md) / [08-05](../../raw/scrapbox_kozaneba/2021-08-05__Kozaneba開発日記2021-08-05.md) — Firebase Local Emulator を構成し、Cypress + Firestore の罠 (experimentalForceLongPolling を useEmulator より前に) を踏み抜く。チュートリアルが動き始める。
- 8/6-7: [開発日記 08-06](../../raw/scrapbox_kozaneba/2021-08-06__Kozaneba開発日記2021-08-06.md) — チュートリアルで「これはかんがえをまとめるツール」を「**かんがえをまとめるデジタル文房具**」と呼び始める。**こざね法のホッチキスでとめる = グループ化** という対応を明示。
- **8/8: [Kozanebaを作ることで何がどうなればいいのか](../../raw/scrapbox_kozaneba/2021-08-08__Kozanebaを作ることで何がどうなればいいのか.md) — この年最大の設計判断**。Keichobot との対話で、当初の「自分が使うツールを作る」と「新規ユーザにわかりにくいから作り直す」が矛盾していることに気づき、目的を整理:
  > 他の人に使われることによって、より良くなるといい。これは自分が使う目的としても良いこと。ブレてた二つの話が一つにまとまった！
  >
  > ツールは「子供」のメタファー — 旅に出したほうが成長する。
- 8/10: [中間発表に向けたまとめ](../../raw/scrapbox_kozaneba/2021-08-10__2021-08-08Kozaneba中間発表に向けたまとめ.md) — 「自分一人にとって使いやすい」軸を据えるなら他人が説明なしで使えるかどうかはどうでもいい、という整合性の崩壊と再構築。**英語圏 → 中国語圏(漢字)** という展開可能性も意識される。「漢字という情報の高密度表記の方法があることが本質的に重要である可能性がある」。
- 8/10: [pKozaneba](../../raw/scrapbox_kozaneba/2021-08-10__pKozaneba.md) — プロジェクトインデックスのハブが Movidea を継いで作られる。
- 8/10: [開発日記 08-10](../../raw/scrapbox_kozaneba/2021-08-10__Kozaneba開発日記2021-08-10.md) — Sentry 導入、エラーバウンダリの限界、フィードバックダイアログ。**チュートリアルの内容を自動テストでカバー** という大方針が確立。

### 2021-08-11〜20: ユーザテスト → 機能の追い込み → リリース

- 8/17: [開発日記 08-17](../../raw/scrapbox_kozaneba/2021-08-17__Kozaneba開発日記2021-08-17.md) — [Kakau](../../raw/scrapbox_kozaneba/2021-08-17__Kozaneba開発日記2021-08-17.md) を試した上で「自由度をポインターで実現する Kozaneba vs キーボードで実現する Kakau」と対比する重要な認識。**Kozaneba はポインターと二本指ジェスチャーがある前提に依存している**。
- 8/18-19: [開発日記 08-18](../../raw/scrapbox_kozaneba/2021-08-18__Kozaneba開発日記2021-08-18.md) / [08-19](../../raw/scrapbox_kozaneba/2021-08-19__Kozaneba開発日記2021-08-19.md) — Forum 開設、Scroll での全体表示、splitダイアログに Replace、ユーザページ(過去 Ba の一覧)、コピーテキスト、ヘルプ目次。`ついつい技術的にできるかできないかあやしいギリギリを攻めたくなるが、それをやると試作品が床に散らばった部屋みたいになって大部分のユーザは快適に過ごせないので僕を隔離する必要がある` という自己観察も書かれる。
- 8/20: [開発日記 08-20](../../raw/scrapbox_kozaneba/2021-08-20__Kozaneba開発日記2021-08-20.md) — リードオンリー共有を最優先と決定 (「ユーザによる拡張性を見せるためにはまず作ったものを壊されずに見せる必要がある」)。日本語 / 英語フォーラム作成。
- 8/20: [かんがえをまとめるデジタル文房具Kozaneba](../../raw/scrapbox_kozaneba/2021-08-20__かんがえをまとめるデジタル文房具Kozaneba.md) — 公式の自己紹介ページ。3 つの目玉機能 (グループを畳む / 重要なものを大きくする / ものの間に関係の線を引く) が宣言される。**ただしこの時点ではまだ「線」は実装されていない**。

- 8/30: [開発日記 08-30](../../raw/scrapbox_kozaneba/2021-08-30__Kozaneba開発日記2021-08-30.md) — Cloud Functions で Scrapbox API を叩いて Scrapbox こざねが作れるように。

### 2021-09: 矢印機能 / 物理演算 / 自己拡張デモ

- 9/1: [Kozanebaの次の進む方向についてわかると良い](../../raw/scrapbox_kozaneba/2021-09-01__Kozanebaの次の進む方向についてわかると良い.md) — Keichobot との対話。「タッチ対応 / 矢印 / ユーザ拡張サンプル」のどれをやるか迷い、結論として「**何が必要かを知るためにはまず使うこと**」。これは 10-12 月の「自分で使い込むフェーズ」の宣言。
- 9/1-2: [開発日記 09-01](../../raw/scrapbox_kozaneba/2021-09-01__Kozaneba開発日記2021-09-01.md) / [09-02](../../raw/scrapbox_kozaneba/2021-09-02__Kozaneba開発日記2021-09-02.md) — リンクこざね、Ba 一覧、ローカルバックアップ。Firestore ルールのバグ修正(リードオンリー共有した Ba を別端末で書き換えられる脆弱性)。
- 9/3: [開発日記 09-03](../../raw/scrapbox_kozaneba/2021-09-03__Kozaneba開発日記2021-09-03.md) — **「Kozaneba 開発を作り直す」と宣言**:
  > ユーザ向けのデモを兼ねたせいで本来の「頭を整理する」目的に反した使い方をしてしまった。自分に必要ないのに Scrapbox こざねを置いたりイラスト描いたり。
  この日に決まった方針: 「**矢印機能 / タブレット対応 / Keichobot 連携** を後回しにし、まずは自分が使って必要な機能を見つける」。

最も繰り返し再燃する論点。8/8 [Kozanebaを作ることで何がどうなればいいのか](../../raw/scrapbox_kozaneba/2021-08-08__Kozanebaを作ることで何がどうなればいいのか.md) で一旦「**他の人に使われて成長すること**」に決着するが、9/3 [開発日記](../../raw/scrapbox_kozaneba/2021-09-03__Kozaneba開発日記2021-09-03.md) では「ユーザ向けのデモを兼ねたせいで本来の頭を整理する目的に反した使い方をしてしまった」と揺れ戻す。12/25 [時間軸逆順の整理](../../raw/scrapbox_kozaneba/2021-12-25__時間軸逆順の整理.md) で再度「(1)世の中の人に対する有用さのストーリー (2)サイボウズに対するビジョン達成への有用さのストーリー」と二本立てに整理。**完全な統合はない。常に揺れる**。

### 3. Scrapbox との関係: 「蓄える場 (Scrapbox) / 削っていく場 (Kozaneba)」

8/28 [発散と収束](../../raw/scrapbox_kozaneba/2021-08-28__発散と収束.md) で最も明快に言語化されている:
> 「連想のリンクが蓄えられていて減ることはない場」と「そこから一部だけコピーしてさらに削っていく場」は別のものであるべき。

これと並行して 8/31 [KozanebaでScrapboxのリンクを整理](../../raw/scrapbox_kozaneba/2021-08-31__KozanebaでScrapboxのリンクを整理.md) や 9/3 [ソースコードをScrapbox的に管理](../../raw/scrapbox_kozaneba/2021-09-03__ソースコードをScrapbox的に管理.md) のように、両者を行き来する具体ワークフローが模索されている。12/11 [KozanebaにScrapbox的な思い出し効果をつける](../../raw/scrapbox_kozaneba/2021-12-11__KozanebaにScrapbox的な思い出し効果をつける.md) では、Kozaneba の重要なこざね (拡大したもの、タイトル付きグループ) を Scrapbox のブラケット同様「**非平行的シンボル**」と位置付け、Ba をまたいでつなぐ未実装機能のスケッチがある。

### 4. 近接 vs 線: 「既存の構造を保ったまま新しい構造を入れる方法」

KJ 法から引き継いだ「近接で関係を表現する」だけでは:
- 8/26 [開発日記](../../raw/scrapbox_kozaneba/2021-08-26__Kozaneba開発日記2021-08-26.md) で「日時で塊になってそれ以上どうしようもなくなる」
- 8/27 [ぶら下げることはグループ化ではない](../../raw/scrapbox_kozaneba/2021-08-27__ぶら下げることはグループ化ではない.md) で「グループにした時点で何が親であるかが固定化する」
- 12/8 [体験過程と意味の創造](../../raw/scrapbox_kozaneba/2021-12-08__Kozaneba_体験過程と意味の創造.md) で「**書籍は既に著者によって構造化されている。理解のためにまず歪めずに丸呑みするが、そこに既存の構造が入ってしまって、追加の構造を入れる余地がなくなる**」 → 9 月の矢印機能、12 月の二重線/同等関係の必要性へ。

12/25 [時間軸逆順の整理](../../raw/scrapbox_kozaneba/2021-12-25__時間軸逆順の整理.md) では:
> 1966 年「発想法」で KJ 法を提案した川喜田二郎は、当時の技術では「自由に動かすこと」と「線を引くこと」を同時にできなかったから自由に動かすほうを取った。それは「線がない方が良い」と思っていたわけではない。Kozaneba はそれを同時にできる。

### 5. 「KJ 法 / こざね法 / Kozaneba」のラベル問題

7/15 で「自分が作ってるのは KJ 法より こざね法 寄り」と気づいた後も、12/18 [Kozaneba 修行](../../raw/scrapbox_kozaneba/2021-12-18__Kozaneba修行.md) で:
> 紙でやってきた経験から不便に感じたことを電子化で対処して grouping → Regroup → Kozaneba と作ってきた。**なのでこのプロセスを表現する上で一番近い単語は「Kozaneba を使うこと」なのだ**。略すると「Kozaneba 修行」。

つまり**「Kozaneba ですること」は既存の語彙ではうまく表現できず、Kozaneba 自身が新しい語彙の発生源になっている**。

### 6. 「不確実性削減ムーブ vs 楽さドリブン vs 面白さドリブン」

8/28 [Kozanebaの開発をKozanebaで管理](../../raw/scrapbox_kozaneba/2021-08-28__Kozanebaの開発をKozanebaで管理.md) で自己分析された 3 つのドライブ。8/19 [開発日記](../../raw/scrapbox_kozaneba/2021-08-19__Kozaneba開発日記2021-08-19.md) では「機能は実装できてて出力の質を上げたい」より「あるべきだと思ってるけど存在してない」を優先する、と自分に言い聞かせている。9/3 でも「Scrapbox こざねを置いたりイラスト描いたりして本来の目的に反した」と反省。**この自己観察と自己制御がそのまま Kozaneba の改善要件 (WIP 札、ピン留め、タスクこざね) になっていく**。

### 7. デジタル文房具は「子供」のメタファー

8/8 の決定的な比喩:
> ツールは「子供」のメタファー — 旅に出したほうが成長する。

これは 12/18 [Accessism誕生の記録](../../raw/scrapbox_kozaneba/2021-12-19__Accessism誕生の記録.md) の「**情報をオープンアクセスにする = 永続的超越者との合一**」と地続きの世界観で、**作者は作品の所有者ではない / 作品はコピーされ歪みながら拡散することで価値を持つ** という Kozaneba の OSS 性・無償提供・ユーザ拡張性の前提を支えている。

### 8. 「ユーザ拡張性」を初期段階から重視

8/16 [開発日記](../../raw/scrapbox_kozaneba/2021-08-16__Kozaneba開発日記2021-08-16.md): `長期的目標はユーザによる拡張性`。8/21 から `localStorage.setItem("onLoad", ...)` でロード時スクリプトが動き、8/31 でメニュー追加 API、9/9 で UserScript ダイアログ。10 月以降は触れる頻度が下がるが、設計思想として「**できるだけ多くのものをユーザ拡張可能な API として露出する**」が一貫している。

### 9. テストファースト + 「DOM データ属性で取得」 + 「内部状態を直接セットする API」

7/16 [Cypress勉強会](../../raw/scrapbox_kozaneba/2021-07-16__Cypress勉強会.md) で固まったテスト思想。これは単に「テスト書く」というレベルではなく **デバッグ・開発フロー全体に密着**。8/17 [開発日記](../../raw/scrapbox_kozaneba/2021-08-17__Kozaneba開発日記2021-08-17.md) で「内部状態を作るユーティリティ関数 (ready_two_groups など) を support に置く」アーキテクチャに整理。**この基盤がなかったら 8/16 の DragDrop API 全廃も 9/22 の Runtypes 化もできなかった**。

## 未解決の問い (2021 年中に「あとで考える」「もやもや」「ブレてる」と書かれたもの)

- **矢印を後から編集する UI**。間違って逆向きにつけた、3 項関係を 4 項にしたい、削除したい、を統一的にやる手段がない。年末まで未解決 ([開発日記 12-27](../../raw/scrapbox_kozaneba/2021-12-27__Kozaneba開発日記2021-12-27.md))。
- **タッチデバイス対応**。8/21 から「iPhone はさておき iPad では動いて欲しい」と書かれているが手付かず。「[Kozanebaの次の進む方向についてわかると良い](../../raw/scrapbox_kozaneba/2021-09-01__Kozanebaの次の進む方向についてわかると良い.md)」で 3 つの候補に挙がるが、結局後回し。
- **Ba をまたぐ RELEVANCE 発見**。[KozanebaにScrapbox的な思い出し効果をつける](../../raw/scrapbox_kozaneba/2021-12-11__KozanebaにScrapbox的な思い出し効果をつける.md) でスケッチされたが未実装。
- **辺ラベル (矢印に文字をつける) は三項関係**という認識のみあり ([Kozaneba:言語の現象学について](../../raw/scrapbox_kozaneba/2021-12-11__Kozaneba_言語の現象学について.md))、実装はされていない。
- **「自分のため」 vs 「多くの人のため」の最終決着**は 2021 年中にはつかない。揺れ続けることそれ自体が Kozaneba の運動エネルギー源とも読める。
- **大量こざね時のパフォーマンス**。12/22 で「**そもそも追加し続けるとキャパを超えるので別の場に分けるべき**」と Kozaneba 自体の使い方論で部分解消するが、技術的な改善は未実施。
- **物理演算の位置付け**。9/6 で実装したが「機械的にやっていいのか?」という懸念があり、ピン留めなどで人間の意志を残す方向で逃げている。**「自動レイアウト」を Kozaneba に入れることへの根本的なためらい**は未解消。
- **チュートリアルの多言語化**。8/12 で英語版が始まり、フォーラムも英日 2 つあるが、本格的な多言語化は手付かず。**漢字 (中国語) こそ本質的に重要かもしれない** という気づき (8/10) は宿題化したまま。
- **「自動で単語こざねを作るアルゴリズム」**。10/4 で「凝ったアルゴリズムより、単に単語に刻んで全部こざねにする方が満足度が高いかもしれない」と気づくが、未実装。
- **VR / メタバース上の Kozaneba**。12/23 [2021-12-23](../../raw/scrapbox_kozaneba/2021-12-23__2021-12-23.md) で「平面ではやりづらいものを VR で」と書いたが、2021 年中の試作はなし。
