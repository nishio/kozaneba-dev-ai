## 目的(仮説検証)

**仮説**: 賢い AI Agent は、現 Kozaneba コードの「悪いところ」を簡単に直す。

[3plan議論](3plan議論.md) で示された Plan A(新規プロダクト)/ Plan B(現Kozaneba改造)/ Plan C(全く新規)のうち、**Plan B を一手だけ実行**して仮説の感触を取る。Plan A の判断はこの試行の結果を見てから別途。

ロードマップではなく **1 回の実験**。「全部やる」ではなく「最小・最安価で仮説に決着」が方針。

## 選んだ題材: 辺ラベル UI

選定理由([辺ラベル](../concepts/辺ラベル.md)・[コード構造調査](../sources/kozaneba-code-architecture.md) を踏まえ):

- **データモデルは既に完成**: 2025-09 の [Devin](../entities/Devin.md) PR で `RTLineAnnot.label: String.optional()` 追加・表示までは main にマージ済み
- **残課題が明確**: 入力 UI 動線と、線をクリック可能にする小改修だけ
- **境界が明確**: スキーマ拡張・物理演算・データ永続化に手を入れる必要なし
- **2025 年の最大の機能ニーズ**(wiki 記述ベース)、成功すれば即実用価値
- **失敗しても傷が浅い** = 仮説検証の素直なテストケース

## 渡す仕様(AI Agent 向け)

### 現状

- `work/kozaneba/` の main(コミット 5de81c2 時点)に対する作業
- `src/Global/TAnnotation.ts` の `RTLineAnnot` には既に `label: String.optional()` が存在
- 表示側は [Line.tsx](../../work/kozaneba/src/Canvas/Annotation/Line.tsx) で実装済み(ラベルがあれば中点付近に出る既定実装あり)
- **入力 UI が無い** — 既存の line に対してラベルを後付けする動線が存在しない

### 達成したいこと

ユーザが「線にラベルをつける / 編集する / 消す」を、**思考の流れを止めずに** できるようにする。

### 必須要件

1. **既存の線にラベルを後付けできる**
   - 線をダブルクリック(または同等の意図的操作)で編集 UI が開く
   - 編集 UI は inline(線の上の文字を直接編集する形)が望ましい。modal dialog は避ける
2. **既存データとの後方互換**
   - `label` フィールドが無い既存 line annotation がすべて動き続ける
3. **空ラベル = ラベル無し**
   - 編集 UI で全削除すれば「ラベル無し」状態に戻る(`label: undefined` または空文字列)
4. **線描画モード中(`line_start` != null)はラベル編集 UI を開かない**
   - 線を引いている最中のクリックはこれまで通り「線の終端確定」に使う

### やってはいけないこと(アンチパターン)

- **描いた瞬間に modal dialog を出さない** — 2025-09 Devin 実装の不採用理由([辺ラベル#エッジラベルダイアログが「ウザい」問題への別解](../concepts/辺ラベル.md))。これを再度踏まない
- **線を引いた瞬間に必須入力にしない** — 同上
- **ラベル機能のためにスキーマを破壊しない** — 既存 `label: String.optional()` を使う

### 推奨パターン(任意、優先度順)

1. **後から double-click**(Miro / tldraw / Obsidian Canvas 型)— [線UIサーベイ_2026](線UIサーベイ_2026.md) 参照。最も安全
2. **描いた瞬間 inline caret**(Whimsical / FigJam 型)— 線を引いた直後、中点に薄い caret が出て、書けば書く、書かなければ消える。modal ではない
3. **Kinopio 型 `connection-type`** — `label` を「型」として育てる方向は今回はスコープ外(将来拡張の余地は残す)

### 技術的な障害(既知)

- [AnnotationLayer.tsx](../../work/kozaneba/src/Canvas/Annotation/AnnotationLayer.tsx) は SVG レイヤ全体に `pointerEvents: "none"` を指定している
- 個別 `<line>` は `custom.is_clickable: true` のときだけ `pointerEvents: "auto"` に切り替わる
- 既存の line annotation は `is_clickable` がほぼ undefined = false 相当なのでクリックできない

→ **デフォルト挙動の変更が必要**。「常にクリック可」にすると物体ドラッグ中のヒット判定を線に取られて邪魔になる懸念があるので、設計判断ポイント(参照: [コード構造調査](../sources/kozaneba-code-architecture.md))。

代替案:
- (a) `is_clickable` のデフォルトを true に変える + マウス状態で挙動を切り替える
- (b) `pointerEvents` を編集モード時のみ有効化する
- (c) 線本体ではなく、線の中点に小さなヒットエリア(ボタン or invisible rect)を別途置く

どれを採用するかは AI Agent の判断に任せる。判断理由を PR 説明に書くこと。

### 成功条件

- [ ] 既存 line を double-click(または同等)してラベルを編集できる
- [ ] 編集後に画面に反映される
- [ ] リロードしても保存されている(Firestore)
- [ ] ラベル無しの線が引き続き動く
- [ ] 線描画モード中はラベル編集 UI が開かない
- [ ] 既存テスト(Jest / Cypress)が壊れていない
- [ ] modal dialog を新規導入していない

- 既存テストの破壊の有無
- 所要時間(人間時間 / AI 時間)
- 驚いたこと
- 仮説に対する感触: 「簡単」「中くらい」「全然簡単じゃない」+ 一行コメント
