# Kozaneba git history 2025 要約

`work/kozaneba/` の `git log` を読んで、2025 年に入った主要な設計変更を束ねた要約。個々のコミット列ではなく、**何が設計上の重心移動だったか**に注目している。

## 全体像

2025 年のコード変更は大きく 2 期に分かれる。

- **2025-04: 生存性の回復**
  - React 17 → 18、Firebase 8 → 9/11.6.1 への更新
  - Netlify ビルド設定、`legacy-peer-deps`、lockfile 整備
  - `useEffect` 由来のメモリリーク対策
  - Gyazo 読み込み前のデフォルトサイズ補完
- **2025-08〜09: 空間操作と関係操作の再強化**
  - 壊れたメニューアイコンをローカル PNG に置換
  - Selection menu に `Rotate / Spread / Scale Double`
  - merge を「新しいこざねを作る」から「最大のこざねを生き残らせる」へ変更
  - 線にラベルを持たせる実装

## 1. 依存更新は「新機能」より先に開発継続性を回復する仕事だった

2025-04-26〜27 のコミット群 (`6f440f4`, `f943d65` ほか) は単なるライブラリ更新ではなく、**Kozaneba を今の環境で再び動かせる状態に戻す**ための基盤更新。

- `package.json`, `src/index.tsx`, `src/Cloud/*` が広く更新され、React 18 と Firebase 新 API に適応
- `netlify.toml` と `.npmrc` が追加され、ローカルだけでなくデプロイ経路も再固定
- `package-lock.json` と `yarn.lock` の両方が整理され、2023-01-11 の「npm で詰まり yarn で動かした」不安定さを減らす方向

設計的には、2021 年の「試作を進めるためにまず動かす」フェーズから、2025 年には **過去の試作を現在の依存環境へ接続し直す保守** が必要になったことを示している。

## 2. 安定化の焦点は「見た目」よりイベント寿命と外部依存の制御

`2ea5cbd` は `KeyboardShortcut.tsx`, `TopPage.tsx`, `TinySample.tsx`, `ItemCanvas.tsx` などで `useEffect` のクリーンアップや依存配列を追加している。これは表面的な挙動調整ではなく、**画面を触り続ける道具としての寿命管理**の修正。

同時に `73322c3` は Gyazo アイテムの画像読み込み前にデフォルトサイズを与え、`9be1319` は壊れた Gyazo リダイレクト画像をローカル PNG に置換している。ここでも焦点は「見栄え改善」ではなく、**外部サービスの不安定さで UI が崩れないこと**にある。

つまり 2025 前半の実装は、Kozaneba を「面白い試作」から **壊れにくい作業環境**へ戻すための修理だったと読める。

## 3. 操作の重心が Group から Selection へ寄っている

`803e67d` は Selection menu に `Rotate / Spread / Scale Double` を追加している。既存の Group menu 側にあった変形操作を、**グループを確定しなくても複数選択に対して直接かけられる**ようにした変更。

これは小さく見えて、作業モデルに次の含意がある。

- 「まとめてから操作する」より「今つかんでいるまとまりをその場で試す」
- 永続構造(Group) より一時構造(Selection) を重視
- こざね配置の探索を、より軽い一時操作で回せるようにする

Kozaneba の本質が「完成構造の管理」より「ねりねりの最中の操作」にあるなら、この変更はかなり本質的。

## 4. merge の意味が「新規生成」から「代表を残す」へ変わった

`33b9f39` は merge 時に新しいこざねを作らず、**最も大きいこざねを生き残らせる**挙動へ変更している。

これにより merge は、

- 以前: 複数こざねを吸収して別の新規オブジェクトを作る
- 以後: 既存こざねのうち 1 つを代表として残し、他を畳み込む

という意味に変わる。

この変更の設計含意:

- オブジェクト同一性を壊しにくい
- 既存 annotation を surviving kozane に付け替えやすい
- 「大きく育ったこざね」を核として構造を再編する発想に寄る

つまり merge が「合成結果を新しく作る」より **今ある思考の核を残して再編する操作**になっている。

## 5. 線がついに意味を背負い始めた

`4c9b38d` から `5de81c2` にかけて、線 annotation に `label` が追加された。表示は `src/Canvas/Annotation/LineAnnot.tsx`、データ型は `src/Global/TAnnotation.ts`、作成 API は `src/API/add_arrow.ts`。

これは既存 wiki の文脈ではかなり重要で、2025 年に頻出していた [辺ラベル](../concepts/辺ラベル.md) の要求が、ついにコード上へ入ったことを意味する。

ただし履歴を見ると揺れもある。

- `4c9b38d`: 作成時ダイアログを出してラベル入力
- `3f89056`: そのダイアログ機能を削除
- `5de81c2`: PR としては「線ラベル機能追加」で merge

つまり設計判断としては、

- **線に意味を持たせたい**のは確定
- しかし **入力 UX はまだ固まっていない**

という状態。データモデル上の前進と、操作 UI の未解決さが分離している。

## 6. 2025 の実装全体が示す方向

2025 年のコミット列をまとめると、重心は次の 3 点にある。

- **継続可能性の回復**
  - 依存更新、ビルド修復、イベント寿命修正
- **探索操作の軽量化**
  - Selection ベースの変形、既存こざねを残す merge
- **関係表現の強化**
  - 線ラベル、壊れない線メニュー資産

これを wiki 側の既存論点に接続すると、

- [物理演算](../concepts/物理演算.md): 機械が勝手に動かすかどうかではなく、人間の探索を軽くする変形操作の整備
- [辺ラベル](../concepts/辺ラベル.md): 長年の要求が最初の実装に到達
- [関係を第一級にする](../themes/関係を第一級にする.md): 関係をデータとして持つ方向への最初の小さな一歩
- [活用されなかった機能](../themes/活用されなかった機能.md): 2025 には「未活用」だったものの一部が再び実装対象へ戻っている

## まだ読めていないこと

- この変更群が実際の操作感をどう変えたかは、`git log` だけでは不十分で、必要なら `work/kozaneba/` を起動して確認が必要
- 2025-09 の line label 実装がその後どこまで使われたか、また Scrapbox 系ソース側に対応する記述があるかは未照合
- `SelectionMenu.tsx` の変化は大きいので、必要なら別ページで「Selection 中心設計」だけを掘る価値がある
